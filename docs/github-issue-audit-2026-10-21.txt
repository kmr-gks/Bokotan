#5「データの読み込み失敗時の処理(音声ファイルがないときなど)」
https://github.com/kmr-gks/Bokotan/issues/5

連続再生はデータなし・音声欠損・再生失敗を通知して停止し、理由を保持します。

一方、クイズではAudioSource.load()の戻り値0を確認せず、SoundPoolの読み込み失敗も
利用者へ通知しません。合成した4語の欠損音声で、問題は表示されるものの、音声失敗の
理由がUI更新として送られないことを再現しました。
元のIssue全体を未対応とせず、この残件へ範囲を絞るのが適切です。
根拠: PlayerService.java:151-164,267-279,295-318、QuizCreator.java:57-58,121-136、
AudioSource.java:29-36。対策履歴: 970ecdb、62b6d66。

#6「PIP使用時にPIPボタンを押した時はPIP画面を終了するようにしたい」
https://github.com/kmr-gks/Bokotan/issues/6
判定: 要望の切り替え操作は未実装。
画面のPIPボタンは常にPipActivityを起動します。通知の小窓操作も、既存の小窓があるときは
終了させません。PipActivityにも、ボタン再押下でfinish()する経路はありません。
「再生停止後に空の小窓が残る」という別の問題とは区別して扱います。
根拠: PlayerFragment.java:203-207、StartPipBroadcastReceiver.java:15-17、PipActivity.java:100-143。
今回この操作の端末再実行はせず、起動・終了経路のコードで確認しました。

#9「assetsのファイル名を英語にする」
https://github.com/kmr-gks/Bokotan/issues/9
判定: 元の同梱assetsの問題は、現在の配布では回避済み。
2025-07-26の9b0054bで、旧ファイル名の「プレミアム」をASCIIのpremiumへ変更しています。
現在のビルドに同梱されるのは公開サンプルだけで、そのassets 15ファイルのパスはすべて
ASCIIです。従来の日本語名のassetsが原因で現行アプリが失敗するとは扱えません。
別件として、個人ZIPの日本語ファイル名にはOS間のUnicode互換性の制限を確認しました。
ZIP内の実ファイル名とwords.tsvの参照名が、見た目は同じでもNFC/NFDで異なる場合、
macOS上では取り込めましたが、Android 36では「単語に対応する音声がありません。」と
拒否されました。両方NFC、または両方NFDならAndroidでも取り込めます。
これは個人ZIPという新しい経路の追加改善として管理し、旧assets改名と区別します。
根拠: app/build.gradle:80-81、PrivatePackage.java:20-35,82-85、履歴9b0054b。

追加検証の実測結果
コミット済みコードを一時コピーし、変更は確認用のandroidTestクラスだけに限定しました。
ビルドはコミット済みのGradle 8.14.3 / AGP 8.13.2を使っています。
利用者が編集中のGradle設定のビルド成否や警告件数を検証したものではありません。

Android 36: 4試験成功（不具合を修正したという意味ではなく、現在の挙動を確認する試験）。
1. 再生対象0件 → 理由を通知し、サービスを停止する。
2. 再生対象の音声欠損 → 理由を通知し、サービスを停止する。
3. クイズの音声欠損 → 問題は利用可能だが、音声失敗の通知は送られない。
4. 日本語ファイル名 → NFC同士・NFD同士は成功、NFC/NFD混在は欠損として拒否。
   試験ではid 2400の1語と極小の合成ファイルを使用し、音声コーデックの検証はしていない。

macOS / Java 17の合成ZIP試験:
ASCII名、NFC同士、NFD同士、NFC/NFD混在はいずれも成功。異なる欠損参照は正常に拒否。
この結果から、個人ZIPの名前の扱いにはOS差があることが分かります。
実際のWindows環境や、すべてのZIP作成ソフトを試したわけではありません。
