Bokotan 今後の作業計画
更新日: 2026-10-21
対象: version 1.07および現在のmain

この文書は、これまでの検証記録とコード確認に基づく未完了項目をまとめたものです。
過去に確認した現象、コード上の反映漏れ、今後の追加候補を区別して記載しています。
各項目は実装・確認が終わってからチェックを付け、確認したバージョンも追記してください。

1. 優先して修正する不具合

[ ] 1-1. 設定項目と実際の動作を一致させる
現状:
「覚えた単語を飛ばす」は保存されるものの、再生処理がその設定を参照していません。
「表示順」も選択値を設定していますが、学習処理で利用されていません。
「空白」は加工済みの別音声を選ぶ従来の仕組みであり、取り込んだ音声の無音部分を
自動削除する機能ではありません。
対応:
・各設定の用途と適用範囲を明確にし、動作を実装する。
・対応しない項目は非表示にするか、対応するデータでのみ選べるようにする。
・既存の正解数・不正解数・正解率による条件と整理し、設定の意味を説明する。
完了条件:
公開サンプルとテスト用の個人データで設定の切り替えが動作に反映されること。
未対応の機能を、利用できる設定として画面に残さないこと。

[ ] 1-2. ZIP取り込み成功後に「個人データ」を確実に選択する
現状:
過去の端末検証で、取り込み成功後も「サンプル」の選択が残る現象を確認しています。
現在も選択値を保存してからActivityを再作成する構造で、以前の画面状態の復元と
競合する可能性があります。現在のビルドでも再現確認が必要です。
対応:
画面再作成・状態復元と選択値更新の順序を整理する。
完了条件:
初回取り込み、既存セットの置き換え、画面回転、背面からの復帰後に、
取り込み成功した個人データが選択され、再生・検索・テストで利用できること。
失敗・中止時は既存のデータを維持すること。

[ ] 1-3. 再生終了時にPiPの空の小窓を残さない
現状:
申告用動画の撮影時、再生停止後に文字のない小窓が残る現象を確認しています。
現在の停止処理は小窓の文字を消しますが、小窓自体を終了させていません。
対応:
再生サービスの終了とPiP画面の終了を連動させる。
再生していないときのPiP起動も防ぐ。
完了条件:
アプリ内・通知・PiPの各停止操作とサービス終了後に、空の小窓が残らないこと。
再生中のPiP表示・単語更新・アプリ復帰が引き続き動作すること。

2. 次回の公開前に確認・整理すること

[ ] 2-1. 既存効果音の利用条件を確認する
対象はapp/src/main/res/raw/seikai.mp3とhuseikai.mp3。
出典とアプリ配布に利用できる条件を確認して記録する。
確認できない場合は利用条件の明確な音へ交換するか、効果音を無効化する。
単語・音声の秘密データをGitHubやAIに渡して確認しないこと。

[ ] 2-2. 未使用の権限を整理する
SCHEDULE_EXACT_ALARMとBluetooth関連の権限がManifestに残っています。
実際の使用箇所を確認し、不要な宣言を削除する。
完了条件は、再生通知・イヤホン切断時の停止・ZIP取り込みが正常に動作し、
不要な権限を求めないこと。全ファイルアクセス権限は追加しないこと。

[ ] 2-3. 提出資料と画面・説明を最新ビルドにそろえる
docs/google-playには1.05時点の草案や未定の記載が残っています。
修正済みの項目を整理し、掲載文、サポート連絡先の案内、ポリシーURL、
申告回答、画像・動画が最終ビルドと一致するか確認する。
新しい掲載用アイコンはdocs/google-play/graphicsに追加済みです。
掲載用画像の更新と、アプリ本体のランチャーアイコンの更新を混同しないこと。

[ ] 2-4. 対象年齢と実機での使いやすさを確認する
全年齢という方針に対し、対象とする各年齢で説明や操作が理解できるかを確認する。
日本語・漢字・数値設定・ZIP操作を含むため、幼児向けの適合性は未確認です。
実機の文字サイズ変更、画面回転、検索欄への入力、再生、PiP、Drive/OneDriveの
ファイル選択、取り込みの中止・再試行も確認する。
端末テストの成功だけで、すべての端末・年齢での動作確認が完了したとは扱わないこと。

[ ] 2-5. 次のバージョンと配布物をそろえる
公開済み1.07より後に、mainでビルド情報の表示などが変更されています。
それらをアプリ配布へ反映するときはversionCodeを増やし、VERSION_NAMEも更新する。
登録済み署名鍵でAPK・AABを生成し、Releaseの対象コミットと最終コードを確認する。
Play Consoleには、その最終ビルドの署名付きAABを提出する。

3. 使いやすさを改善する追加機能

[ ] 3-1. 個人データの削除画面を追加する
アプリ全体のストレージ消去やアンインストールをせず、取り込んだ個人データだけを
削除できるようにする。削除対象、学習記録の扱い、確認操作を明確にする。
元のZIPやクラウド上のファイルは削除しないことを画面で説明する。

[ ] 3-2. 複数の個人データセットの保存・切り替えに対応する
現在は一つの個人データセットを置き換える方式です。
複数セットを保持し、表示名と保存容量を確認して切り替えられるようにする。
セットごとの学習記録を混同しないことと、既存形式からの移行を設計する。

[ ] 3-3. 取り込み時の音声の検証とエラー表示を改善する
現在は参照先の存在などを検証しますが、音声が再生可能かは取り込み後の確認が必要です。
破損した音声や非対応形式を検出し、問題のあるファイルと対処方法を案内する。
大容量ZIPを全体ごとメモリに載せないこと、失敗時に既存データを維持すること。

[ ] 3-4. 取り込み中断後の説明と再試行を分かりやすくする
現在はOSによるプロセス終了やクラウド切断後の自動再開に未対応で、ZIPの再選択が必要です。
まず、中断したこと、従来データの状態、やり直す手順を明示する。
途中からの再開機能は別途検討する。ファイル提供元の再読み込み可否、権限の保持、
展開途中のデータの整合性を確認してから実装する。

4. その後の追加候補（必須対応ではない）

[ ] 4-1. 個人データの例文・単語と例文の混合再生に対応する
現在の個人ZIP形式は単語用です。形式の拡張と既存ZIPとの互換性を設計する。

[ ] 4-2. テストのヒント機能を設計する
未実装のヒントボタンは1.06で非表示にしています。
ヒントの内容と学習記録への影響を決め、実装・検証できてから表示する。

[ ] 4-3. 継続的な品質確認と保守を改善する
今回追加した端末テストを今後の変更でも実行する。
必要に応じてCIのエミュレーター試験を導入し、最小対応OSと最新OSでの確認を広げる。
Lintの既存警告、重複するリソース配置、古いビルド設定を影響範囲ごとに整理する。
